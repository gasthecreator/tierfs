## [Unreleased]

### Added
- `tierctl service` is mutation-tested (`scripts/tierctl_mutants.py`, 40 more mutants): 12 gaps found and closed in `tests/service_cli_test.py` (unknown actions and options, a value missing, an `=` inside a value, the default log folder, no home directory, names with a slash, a directory as the binary, an unchanged plist left untouched); one documented equivalent.
- `tierctl discover` is tested against a real announcing device (`tests/discover_cli_test.py`, part of `make test`) and mutation-tested (`scripts/tierctl_mutants.py`, 27 mutants, all killed); the mutation runner can run Python tests. `tests/pairings_test.cpp` was not part of `make test` by mistake and is now.
- The daemon is mutation-tested (`scripts/daemon_mutants.py`, 135 mutants): the first run found 46 survivors, now closed with tests for the configuration checks, the control socket, devices that are looked up (including on the real network), the free-space thread, the plan/approve flow, backup age boundaries and the garbage-collection report; the 8 left are documented equivalents. `DaemonConfig::discover` can now report why it could not look.
- A menu-bar app (ADR-0019, `macos/`): the space level, the devices and any problem at a glance, and a review window that shows the plan in the daemon's words with a button that approves exactly that plan (after one more confirmation). It only talks to the control socket; the control client is tested against a stand-in daemon (`make test-macos`).
- Android agent, more complete: the choice to be on is saved and the service comes back as it was after Android stops it (`START_STICKY`) and, if asked, when the phone starts or the app is updated; a button asks Android to exempt it from battery optimisation; the store can live on shared storage / a memory card (`--lock-dir` keeps the lock in internal storage); `android/fetch-deps.sh` fetches SQLite and OpenSSL against pinned hashes; `android/build.sh` builds arm64, x86_64 and 32-bit ARM and can sign with your own key. The screens for several Macs were run on the emulator for the first time (add, list, revoke).
- CI builds the device side on Linux (`make linux-test`: server, store, secure channel, pairings) and the Android APK for all three ABIs. Recipes that pipe a test through `tail` now fail when the test fails (`pipefail`).
- Stable inode numbers (ADR-0018): `st_ino` comes from the file id for a file with one name (kept across rename, offload, hydrate and restart) and from the place in the origin for hard-linked files, directories and untracked files, so hard links show one number; `getattr` and `readdir` agree; the driver passes it with `-o use_ino` (`useino=0` turns that off). Not verified on a mount. Locks of a hard-linked file are shared by all its names, and a lock taken before the second name existed moves with the file.
- Device trash (ADR-0017): a sweep or a deletion on a device moves the files into `<store>/trash` and removes them for good after `--trash-days` (default 7; 0 = at once), so a wrong sweep or a Mac that lied about a chunk list can be undone: `tierfs-device <store> --list-trash | --restore-trash[=SECONDS] | --empty-trash` (stop the device first). Restoring uses the normal upload paths and the saved chunk list. `GC_STATUS` reports the trash; `gc-run` says how much each device holds. Freed space on a device now comes back after the retention period.
- Fuzzing (`tests/fuzz_test.cpp`, `make test-fuzz`, part of `make test`): a seeded structure-aware fuzzer under ASan/UBSan for the wire reader, frame decoding, the secure-channel handshake and sealed frames (every single bit flip refused; replays and reordering refused), the recovery phrase, the discovery record and device entries, service options and the plist, the control socket, and an open and a paired device server over real sockets (mutated requests of every kind; it must survive, keep answering, and keep an intact store). `TIERFS_FUZZ_SEED` replays a run, `TIERFS_FUZZ_SCALE` makes it longer.
- One pairing per Mac (ADR-0016, `core/pairings.*`): `tierfs-device <store> --add-pairing=LABEL [--pairing-allow-delete]`, `--list-pairings`, `--revoke-pairing=KEYID`. Each Mac has its own secret, can be revoked alone (refused at once, open connections end at their next request), and has its own right to delete (`DELETE_MANIFESTS`/`SWEEP` answer EPERM without it). The original `pairing.key` keeps working and may delete. A pairing file that is unreadable, too open, mismatched or mistyped stops the device (it never falls back to open). Discovery announces one record per pairing; the Android app lists, adds and revokes pairings.
- Android agent (ADR-0015, `android/`): the existing device server compiled with the NDK and hosted by a small app (foreground service in its own process; always paired; pairing code only on the phone's screen; announces itself with `NsdManager`). `android/build.sh` builds the APK without Gradle; `tests/android_smoke.cpp` offloads to a phone and reads back from it alone (tried on an arm64 emulator, not on hardware). The device server and store now build on Linux/Android (`fsync` where macOS uses `F_FULLFSYNC`), and a store directory that cannot be locked is reported as such.
- Device discovery with Bonjour (ADR-0013): `tierfs-device ... --advertise[=NAME]` announces a paired device as `_tierfs._tcp`; `tierctl discover` lists what is announced; `devices=mdns:NAME@keyid` follows a device that changes address (an announcement is only a locator: the key id must match a pairing secret the Mac holds, and the connection authenticates as always); `tierctl restore --device mdns:...` finds a device during recovery. An unpaired device refuses to advertise.
- The free-space check has its own thread (`spacecheck=N` seconds, default 30; ADR-0014) so a long copy never delays the warning; a notification that could not be shown is retried and reported instead of counted as said; the notification names what stands in the way (recovery phrase, backup statement, devices); thresholds are options (`lowgb`, `criticalgb`, `lowpct`, `criticalpct`); `tierctl space <ledger>` shows the level, thresholds and when you were last told.
- Space plans a person can read and approve (ADR-0012): `tierctl plan <ledger> [free-now] [GiB]` shows what would move in plain words (folders, the largest files, what happens to each file, what is left alone, what blocks it) and moves nothing; `tierctl approve <ledger> <plan id>` runs exactly that plan, once, while it is fresh and nothing blocks it. The low-space notification now says how to review.
- Hard links and advisory locks (ADR-0011). `link(2)` works for regular files (an offloaded source is brought back first); a file with more than one name is never offloaded (the drop engine refuses, the policy skips it) so the quarantine never shares bytes with a live name; link counts are reported. `flock` and `fcntl` byte-range locks are emulated in the daemon (`core/locks.*`) with POSIX semantics per file identity and lock owner; waiting is a polling loop in the driver that ends when the kernel interrupts the request.
- `tierctl service plist|install|uninstall|status`: tierfsd as a LaunchAgent. The plist is rendered and checked by `core/service.*` (absolute paths; the mountpoint may not be, contain or lie inside the origin; the key only from the Keychain or a key store; no comma or control character in option values) and does not restart a crashed mount or start at login unless asked. `install` writes the plist and starts nothing; `--load` additionally needs `TIERFS_I_ACCEPT_A_REBOOT=1` while mounting is unproven (ADR-0006).
- Read-ahead for offloaded files: after three sequential reads the overlay fetches the next chunks in the background (window 1, 2, 4 ... up to `readahead=N`, default 4, never more than a quarter of the cache), verified and cached like any other fetch; a chunk wanted by the reader and the read-ahead at once is fetched once. `-o readahead=0` (negative in the C options) turns it off.
- Garbage collection on the devices (ADR-0010): the ledger decides which old versions and deleted files to forget (permanent, hash-chained, never a live file's current version, only with a newer version held by fresh audits, deleted files after 30 days), devices delete exactly the named manifests and sweep chunks no manifest lists (a database trigger protects listed chunks), only if paired or started with `--allow-delete`; `tierctl control <ledger> gc-plan|gc-run`, daemon option `gc=1`. Device store schema 2 and ledger schema 3 migrate on open.
- Secure channel for the device protocol (v4): pairing secret, ephemeral X25519, AES-256-GCM frames with counters (ADR-0009); known-answer vectors from an independent reference.
- Device authentication, wired in: `tierfs-device <store> --show-pairing-code` / `--new-pairing-code`; a paired device speaks only the authenticated channel and may listen on any address, an unpaired one stays plaintext and loopback-only; `tierctl pair <host:port> --store keychain|dir:PATH` keeps the secret in the Keychain; devices are named `host:port@keyid` in the daemon and in `tierctl restore --store SPEC`, and `restore --pairing-file FILE` lets a disaster recovery start from the recovery phrase plus the codes written on paper.
- The master key can live in the login Keychain: `tierctl init <ledger> --store keychain`, `tierctl check-phrase --store keychain <ledger>`, daemon option `keyfile=keychain` (key sources: `keychain`, `dir:PATH`, or a key file). The real-Keychain tests are opt-in (`TIERFS_TEST_KEYCHAIN=1`).
- Dated backup statements: a file may leave the Mac only if it was created or changed before the recorded backup, and the statement expires after 30 days; `tierctl check-backup` (read-only Time Machine report); the policy skips files the backup does not cover.
- Case- and Unicode-insensitive name handling (unique folded key, schema version 2 with migration), matching APFS.
- Repository standards: LICENSE (MIT), SECURITY, CONTRIBUTING, CODE_OF_CONDUCT, CODEOWNERS, issue and PR templates, ADRs, threat model,
  CodeQL, Scorecard and Dependabot, pinned CI actions, `make test`.
- `tierctl init`, `check-phrase`, `ack-backup`, `control`, `restore`, `ledger-status`.
- `tierfsd`: daemon with start-up recovery, scanner, maintenance thread and a private control socket; FUSE-T driver.
- Overlay filesystem semantics: reads from local or remote bytes, writes with a write gate, hydration, namespace operations, extended attributes.
- Disaster recovery from the recovery phrase and any one device.
- Policy layer: space levels, cold-file planning, scoped expiring consent, background replication.
- Drop engine with quarantine, purge and restore; replicate engine with audits; device store and protocol v3; deterministic encryption; ledger.

### Changed
- Frames are read into memory only as the bytes arrive (`read_grow`): a peer that announced a 16 MiB frame and sent nothing used to cost 16 MiB per connection (fuzzing showed it).
- Service paths and option values must be well-formed UTF-8: a path with other bytes made a plist that the system's own parser refuses (found by fuzzing, with the mutation-tested check in `core/service.cpp`).
- `tierctl ack-backup` now records the time; ledgers with an undated statement refuse to move files until it is run again.

### Known issues
- The FUSE-T mount layer is unproven on real hardware: mounting reset the development machine (macOS NFS-client panic, ADR-0006).
- The device server has no authentication; see the threat model.
